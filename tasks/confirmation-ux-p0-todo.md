# Confirmation UX P0 Checklist

- [x] P0.0：建立确认队列 view model 与去重回归测试。
- [x] P0.1：实现 Trip Summary、Confirm Queue、Confirmed Items，以及系统推荐与快捷地点搜索。
- [ ] P0.1：与用户检查 v0 的信息层级、文案和密度后再继续。
- [x] UX-01：地点服务不可用时返回可恢复状态，不把服务故障显示为“没有候选”。
- [x] UX-02：地点搜索没有结果时回显用户查询，并说明可补充城市、街区、附近地标或准确地址。
- [x] UX-03：确认地点时 provider 临时不可用会保持 Draft 不变，明确说明未确认状态并提供安全重试。
- [x] UX-04：确认工作台的主要按钮、编辑入口和表单控件具有统一、可见的键盘 focus ring。
- [x] UX-05：真实 Draft 确认流程的 E2E 契约已迁移到确认工作台；编辑失败只显示一次上下文相关的恢复提示。
- [x] UX-06：地点核验服务临时不可用时，浏览器流程验证地点保持未确认、Draft 不变，并可在服务恢复后安全重试。
- [x] UX-07：LLM 不再把输出要求或软节奏语言臆测为“预约/有安排”固定安排；只有原始输入可由确定性解析佐证时才保留这种泛化固定项。
- [x] UX-08：确认队列默认只展开最优先的一项；其余地点和澄清项收敛为标题、原因与单个行动，移动端触控入口不少于 44px。
- [x] UX-09：已确认的直输必去地点会作为 provider 核验 POI 进入首版路线预览；不再被误显示为“暂不设定必须到达的地点”。
- [x] UX-10：路线预览被未核验的必去地点阻止时，改为说明可恢复原因与重新选择地点的行动，而不是笼统的生成失败提示。
- [x] UX-11：当 Draft 被阻止但没有可直接确认的项目时，确认清单不再错误显示“可以生成首版路线”，而是引导用户修改原始需求。
- [x] UX-12：路线预览请求遇到 stale Draft 时，当前页面会自动载入最新版本并提示重新生成，而不要求用户退出重进。
- [x] UX-13：无可直接确认项目的阻断状态提供就地“修改原始需求”行动，不要求用户先滚动到底部寻找恢复入口。
- [x] UX-14：首版路线预览请求等待过久会安全停止，并明确保留确认信息与提供重新生成入口。
- [x] UX-15：可恢复的路线预览服务失败会明确说明确认信息未变并引导重新生成，不再只显示笼统失败。
- [x] UX-16：可恢复的路线预览失败提供独立“重新生成路线预览”行动，不要求用户在页面底部判断主按钮是否可用。
- [x] UX-17：已确认信息仍无法安全进入路线规划时，按真实阻断原因说明需要调整的时间、固定安排或地点资料，不再只显示通用失败。
- [x] UX-18：可由旅行时间或目的地修复的路线阻断，提供对应的就地编辑入口，不要求用户返回上一层重新找字段。
- [x] UX-19：主动重新整理旅行信息会开启新的幂等编译尝试，而网络重试仍复用原尝试，避免导入地点变化被旧请求回放或冲突拦住。
- [x] UX-20：路线预览因已选地点资料变化被阻断时，直接提供“重新整理旅行信息”行动，不要求用户在页面其他区域寻找恢复入口。
- [x] UX-21：未完整核验的必去地点阻断路线预览时，提供“前往确认该地点”入口，并展开、定位和聚焦确认清单中的首个待确认地点。
- [x] UX-22：固定安排地点未核验阻断路线预览时，提供“前往确认预约地点”入口，并定位到对应类型的确认项。
- [ ] P0.2：完成空态、失败、stale、键盘与移动端体验。
- [ ] P0.3：完成 fixture 浏览器路径与本地 provider 验证。
- [ ] P0.3：完成 UI 五维复盘、测试、`git diff --check` 与提交。
