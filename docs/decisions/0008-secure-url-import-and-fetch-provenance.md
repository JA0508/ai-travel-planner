# ADR-0008: Secure URL Import and Fetch Provenance

## Status

In review

## Date

2026-07-16

## Context

Source-to-Executable Trip Workspace needs to ingest web guides without turning
the backend into an unsafe crawler or allowing third-party web content to mutate
trip state. A user-provided URL is not trusted input. Even a successful HTTP
200 response is only source material that must be normalized, bounded, audited,
derived into plain text, and reviewed by the user before it can become a
TripCandidate.

## Decision

URL import is a security boundary, not a normal HTTP GET.

The server owns URL parsing and normalization. It allows only `http` and
`https`, rejects userinfo, sensitive query parameters, unsupported ports,
single-label internal hosts, metadata hosts, private destinations, and
ambiguous numeric host forms.

DNS validation is explicit. A `HostResolver` abstraction resolves every redirect
host. All returned A/AAAA addresses must be public. Mixed public/private answers
reject the whole host.

DNS rebinding protection is enforced by the transport boundary. The production
transport connects to an already-approved resolved IP while preserving the HTTP
Host header, TLS SNI, and certificate hostname verification. TLS verification is
not disabled. Fixture tests can inject a peer mismatch and verify the request is
rejected.

Redirects are handled manually. Each hop is normalized, checked for sensitive
parameters, DNS-resolved, peer-validated, and recorded. HTTPS-to-HTTP downgrade,
loops, private targets, unsupported schemes, and redirect limit violations fail.

Robots policy is fetched through the same secure boundary. `404` and `410` mean
no explicit robots prohibition. `401` and `403` disallow. Timeout, 5xx, DNS, or
network failure returns `robots_unavailable`; this slice fails closed and asks
the user to paste text instead. There is no robots bypass switch.

The HTTP client sends only GET with minimal headers, no cookies, no
authorization, no browser session, no user-supplied headers, no proxy
environment, bounded timeouts, bounded body streaming, and bounded
decompression. Only text-like MIME types are accepted: `text/html`,
`text/plain`, and `application/xhtml+xml`.

Raw fetched bytes are stored as a private `SourceArtifact` with
`artifact_type=url_document`. The reviewable source is a separate
`artifact_type=derived_text` artifact generated by a deterministic document text
extractor. `ArtifactDerivation` links child to parent with transformer version
and checksums.

`URLFetchSnapshot` is immutable and records the sanitized request URL, normalized
request URL, sanitized final URL, redirect chain, robots result, status code,
content metadata, checksums, fetcher/policy versions, and warning codes. It does
not store cookies, authorization, raw secret query values, response body,
storage path, capability, or full DNS trace.

HTML is parsed into deterministic plain text without JavaScript execution,
headless browsing, login bypass, subresource downloads, or iframe rendering.
Mention spans always point into the derived text artifact, never raw HTML.

URL import reuses the existing import review pipeline:

```text
URLImportRequest
→ URLFetchSnapshot
→ raw SourceArtifact
→ ArtifactDerivation
→ derived SourceArtifact
→ ImportJob
→ ExtractedMention
→ ResolvedPlaceCandidate
→ ImportReviewDecision
→ TripCandidate
```

Import commit still creates or reuses `TripCandidate` only. It does not create a
`TripRevision`, mutate TripIntent, run the planner, schedule a stop, or admit a
candidate into an itinerary.

The frontend shows derived plain text plus safe provenance metadata. It never
uses an iframe and never renders raw HTML. The original source link opens in a
new tab with `noopener noreferrer`.

## Consequences

### Positive

- URL imports can be reviewed and replayed offline through immutable evidence.
- SSRF and DNS rebinding protections are testable without live network access.
- Redirect and robots behavior is explicit in provenance rather than hidden in
  an HTTP library.
- Raw HTML and derived text remain separate, making mention spans stable and
  safe for review.
- Future image/PDF adapters can reuse the artifact, derivation, review, and
  TripCandidate boundary without bypassing human confirmation.

### Negative / trade-offs

- Static extraction misses pages that require JavaScript rendering.
- Robots fail-closed can block otherwise useful imports.
- Login walls and anti-bot pages are not bypassed.
- The current HTML main-text extractor is deterministic but intentionally
  conservative.
- Local artifact storage remains a development-oriented storage backend.

## Alternatives considered

- **Use `requests`/`httpx` with automatic redirects:** rejected because it would
  hide per-hop DNS and peer validation and could trust environment proxy
  behavior.
- **Only pre-check DNS then let the HTTP client resolve again:** rejected because
  it does not protect against DNS rebinding.
- **Disable TLS verification for IP pinning:** rejected because it would trade
  SSRF defense for origin authenticity failure.
- **Execute JavaScript or use headless Chromium:** rejected for this slice
  because it expands the trust boundary into browser automation and login-wall
  ambiguity.
- **Render the remote page in an iframe:** rejected because it leaks browser
  context, enables third-party tracking, and confuses source review with remote
  execution.
- **URL import directly creates TripRevision:** rejected because source import is
  evidence acquisition and human review, not an executable itinerary mutation.
