# Planning Record UI

The candidate page is a decision surface, not an event console. It keeps a
compact strategy selector above a complete day-by-day route timeline and a
single save action. The selected route keeps its current day when switching
options.

`查看规划记录` uses ordinary language: what the traveler confirmed, which fixed
arrangement was preserved, how many routes were generated, which route was
saved, and source snippets when expanded. Run IDs, hashes, policy versions, and
database status are not shown by default.

Refresh restores the original candidate set. Expired runs explain that old
route proposals are not used and offer one regeneration action. Selected runs
offer the saved itinerary.
